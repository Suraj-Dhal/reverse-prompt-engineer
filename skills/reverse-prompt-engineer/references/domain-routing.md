# Domain routing playbooks

Apply only the checks that materially fit the target. Domain checks supplement the general reconstruction workflow; they do not override explicit user requirements, source precedence, or safety rules.

## Writing and content

Check audience, purpose, channel, tone, point of view, voice, structure, section requirements, terminology, language, length, reading level, examples, citation expectations, and prohibited content. Separate visible style clues from inferred instructions.

## Research and reporting

Check research question, scope, as-of date, source quality, inclusion/exclusion criteria, citations, verification, method, limitations, competing explanations, and uncertainty. If current facts matter and browsing is available and authorized, verify them; otherwise disclose the limitation. Never invent source checks or citations.

## Business and strategy

Check decision-maker, business context, objective, frameworks, assumptions, alternatives, trade-offs, scenarios, metrics, risks, recommendation logic, dependencies, implementation, and decision criteria. Preserve each named prospect/case and the condition that changes the recommendation. Do not invent market facts.

## Code and software

Check language, runtime, environment, inputs/outputs, interfaces, dependencies, version constraints, tests, failure handling, performance, and security. Include only facts supported by the prompt, target, or supplied context; use placeholders for unknown runtime details. Never state code was executed unless it was.

## Data and quantitative analysis

Check data provenance, variable definitions, units, transformations, formulas, missing values, assumptions, statistical method, uncertainty, visualization, and interpretation. Do not invent data or imply causation from correlation. Preserve denominators, comparison groups, timeframes, rounding, and units when material.

## Image, video, audio, website, and design artifacts

Use observable features and user-provided context: subject, composition, framing, hierarchy, layout, typography, palette, spacing, lighting, style, motion, timing, sound, medium, and output constraints. For websites, distinguish visible design/content from hidden implementation. Do not invent source code, responsive behavior not observed, exact CSS values, hidden metadata, identity, model, or production settings.

## Agents and tool workflows

Check role, objective, plan, permissions, access boundaries, input/output schemas, decision criteria, stopping rules, retries, failure reporting, escalation, and auditability. Differentiate requested behavior from actual platform capability. Never encode unauthorized actions or claim an integration/execution without evidence.

## Education and instructional materials

Check learner level, prerequisites, learning objectives, syllabus/scope, explanation depth, examples, practice tasks, answer keys, assessment criteria, language, and accessibility needs. Do not assume a curriculum or grading standard that was not supplied.

## Other domains

Use the closest general checklist, disclose material unknowns, and avoid imposing an irrelevant discipline-specific framework.
